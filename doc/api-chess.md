# 国际象棋接口文档

AI 对弈服务（`chess-lab-server`）里国际象棋这条链路的调用说明，给前端对接用。
斗兽棋、通用约定与错误码的完整说明见 [`api-jungle.md`](api-jungle.md)，本文自成一体，只对接国际象棋读这一份就够。

| | |
|---|---|
| Base URL | `http://localhost:8080`（端口见 `server.port`） |
| 请求 / 响应体 | `application/json`，UTF-8 |
| 鉴权 | 无。模型密钥在服务端配置，不经过调用方 |
| 跨域 | 只放行 `http://localhost:5173` 与 `http://127.0.0.1:5173`，方法限 `GET` / `POST`（`WebConfig`） |

| 接口 | 用途 |
|---|---|
| `GET /api/ai/models` | 取棋手清单，与棋种无关 |
| `POST /api/chess/ai/move` | 让 AI 在候选着法里选一步 |

## 先读这一段：调用方要理解的三件事

**1. 合法着法由调用方算，后端只做选择。** 后端不实现国际象棋规则：不生成着法、不判将军、不判胜负。
每次请求要把当前局面**和你自己算好的全部合法着法**一起发过来，后端把这些着法编号塞进提示词，
让模型返回其中一个编号。规则因此只有一份实现，在前端的规则引擎里。

**2. 这个接口几乎不会失败。** 模型返回越界编号、调用失败、没配密钥、连接名写错——
全部落到启发式兜底，仍旧返回一条合法着法，只是响应里 `fallback: true`。
会返回错误码的只有调用方自己的问题：棋手 id 不存在、请求体不合法。

**3. 没有超时，一手棋可能要等 3 分钟以上。** 服务端调用模型时不设读超时、不重试。
带长思考的推理模型一手 170–220s 是常态。**调用方务必把自己的 HTTP 超时放宽**，
否则会在服务端还在等模型时先行断开。

## 记法约定

接口里不出现 `[行, 列]` 坐标，局面和着法一律用国际象棋的标准记法：

| 用在哪 | 记法 | 说明 |
|---|---|---|
| `fen` | FEN | 局面。六个字段都要带：摆子、行棋方、易位权、吃过路兵格、半回合计数、全回合数 |
| `legalMoves[].uci` | UCI | 机器坐标，`起点` + `终点` + 可选升变子。兜底评分靠它定位起落格 |
| `legalMoves[].san` | SAN | 人类棋谱，带吃子、将军、将杀、升变标记。原样进提示词 |
| `history[]` | SAN | 开局至今的着法 |
| `side` | `w` / `b` | 白 / 黑。FEN 里大写字母是白子、小写是黑子 |

几类特殊着法的写法：

| 着法 | `uci` | `san` | 要点 |
|---|---|---|---|
| 普通走子 | `g1f3` | `Nf3` | |
| 吃子 | `f3e5` | `Nxe5` | SAN 带 `x` |
| 吃过路兵 | `e5d6` | `exd6` | 落点是空格，但 SAN 仍带 `x`，兜底按吃掉一个兵计分 |
| 升变 | `e7e8q` | `e8=Q` | UCI 第五位是升变子，小写 `q` `r` `b` `n` |
| 吃子升变并将军 | `e7d8q` | `exd8=Q+` | |
| 短易位 / 长易位 | `e1g1` / `e1c1` | `O-O` / `O-O-O` | UCI 写王的起落格；SAN 用字母 `O`，不是数字 `0` |
| 将军 / 将杀 | `d1h5` / `d1f7` | `Qh5+` / `Qxf7#` | SAN 带 `+` / `#` |

**SAN 里的 `x` `+` `#` 标记必须带全。** 提示词让模型直接采信这些标记，不再自己推；
兜底也只靠它们识别吃子、将军与将杀。少了标记，一步将杀在兜底眼里就只是普通走子。

### 前端规则引擎生成记法时要守的格式

后端不校验记法，格式不对也照收，但模型和兜底会读错。各项后面标了读错的后果：

**UCI**

- 固定 4 位，升变 5 位：`起点格 + 终点格 + 升变子`，格子写小写的 `a`~`h` 加 `1`~`8`
- 升变子写小写：`q` `r` `b` `n`，这是 UCI 的标准写法。兜底按这一位的子力价值给升变打分
- 易位写**王**的起落格：白方 `e1g1` / `e1c1`，黑方 `e8g8` / `e8c8`。不要写成王走到车的格子（`e1h1`）
- 兜底用 `uci` 的前两位去 FEN 里查走的是哪个子，起点格写错了，吃子评分和「无故走王」的扣分都会算错

**SAN**

- 棋子字母大写：`K` `Q` `R` `B` `N`，兵不写字母
- 吃子带 `x`，兵吃子前面写起点列：`exd5`。吃过路兵也照这个写，不加 `e.p.`
- 升变写 `=` 加大写子：`e8=Q`、`exd8=N`
- 易位用字母 `O`：`O-O`、`O-O-O`。兜底按 `O-O` 开头识别易位，写成数字 `0-0` 就认不出来
- 将军结尾加 `+`，将杀结尾加 `#`，二者只写一个
- 两个同种子都能走到同一格时要写消歧义：`Nbd2`、`R1e2`、`Qh4e1`。不写不影响兜底，但模型读到的棋谱会有歧义
- 不带 `!` `?` 这类注释符号

**FEN**

- 吃过路兵格建议只在**本手真能吃过路兵**时填（如 `e3`），其余时候写 `-`。只要这一格不是 `-`，
  提示词里就会写「本手可以吃过路兵落到 e3」。按 FEN 原始规范，兵每走两格都要填这一格，
  但那样的话，旁边没有能吃它的兵时，模型也会被告知可以吃
- 半回合计数和全回合数照实写。模型要靠半回合计数判断离五十步和棋还有多远

## GET /api/ai/models

取棋手清单，给前端的模型下拉框用。棋手在 `application.yml` 的 `chess.ai.players` 下配置，
与棋种无关——同一批棋手既下斗兽棋也下国际象棋。

无请求参数。

**200 响应**

```json
[
  { "id": "qingyun", "name": "青云", "code": "QINGYUN" },
  { "id": "xuanji",  "name": "玄机", "code": "XUANJI" }
]
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 棋手标识，调用 `/move` 时作为 `playerId` 传回 |
| `name` | string | 中文名 |
| `code` | string | 英文代号 |

清单里出现某个棋手，不代表它背后的模型此刻可用——不可用时 `/move` 照常返回着法，只是走兜底。

## POST /api/chess/ai/move

在调用方给出的候选着法里选一条。

### 请求体

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `playerId` | string | 是 | 棋手 id，取自 `/api/ai/models` |
| `side` | string | 是 | AI 执哪一方，只能是 `w`（白）或 `b`（黑） |
| `fen` | string | 是 | 当前局面的完整 FEN，不能为空白 |
| `history` | string[] | 否 | 开局至今的 SAN 着法序列，如 `["e4", "e5", "Nf3"]`，模型靠它看来路、留意三次重复 |
| `legalMoves` | array | 是 | 当前局面的全部合法着法，非空 |
| `legalMoves[].i` | int | 是 | 着法编号，响应的 `index` 就是这个值 |
| `legalMoves[].uci` | string | 是 | UCI 记法，见上文「记法约定」 |
| `legalMoves[].san` | string | 是 | SAN 记法，`x` `+` `#` 标记必须带全 |

各字段从规则引擎的哪里取：

| 字段 | 取值 |
|---|---|
| `side` | 当前轮到走的一方，也就是 FEN 第二个字段 |
| `fen` | 规则引擎导出的当前局面 |
| `history` | 开局以来每一手的 SAN，和 `legalMoves[].san` 用同一套生成逻辑 |
| `legalMoves` | 当前局面的全部合法着法，每条同时给出 UCI 和 SAN，`i` 从 0 起顺序编号即可 |

### 几处不报错、但会让结果变差的情况

后端对 `fen`、`side`、`history` 只做最基本的校验，下面几种情况都会照常返回 200，
但模型拿到的是错的信息，棋会下歪。请调用方自己保证：

- **`side` 要和 FEN 的行棋方一致。** 后端不比对这两个值。不一致时提示词里会同时出现
  「你执白方」和「轮到黑方走」，模型会被这两句矛盾的话搞糊涂。直接取 FEN 的第二个字段填 `side` 就不会出错。
- **`history` 只在从标准初始局面开始的对局里传。** 后端假定第一步是白方走的第 1 回合，
  排成 `1. e4 e5 2. Nf3` 给模型看。残局练习、摆谱这类从自定义 FEN 开始的对局，
  回合号和黑白都会对不上，这时**不传 `history`**，局面信息 FEN 里已经全有。
- **`fen` 写坏不会报错。** 看不懂的字符跳过、缺失的字段按默认值补（白方走、无易位权、无过路兵格），
  但棋盘渲染和兜底评分会跟着失真。
- **`legalMoves` 要给全。** 提示词里写死了「候选即当前局面全部合法着法」，
  只给一部分，模型会以为别的着法都不合法。

关于 `i`：响应里的 `index` 是**某条着法的 `i` 值**，不是数组下标。按 0 起连续编号时两者恰好一致，
但后端只校验「返回的编号在 `i` 的集合里」，不要求连续。

### 200 响应

```json
{ "index": 0, "reason": "出马保护 e5 兵。", "fallback": false }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `index` | int | 选中的着法编号，必定是请求里某条 `legalMoves[].i` |
| `reason` | string | 选择理由，一句中文 |
| `fallback` | boolean | `true` 表示这一手不是模型选的，是启发式兜底 |

前端拿到 `index` 后，按 `i` 找回那条着法，用它的 `uci` 或 `san` 在本地走子即可。

### fallback 为 true 时

`reason` 会说明是哪一种，可以直接展示给用户：

| `reason` | 起因 |
|---|---|
| `AI 未给出有效着法，已按子力价值兜底。` | 模型返回的编号不在候选里，或调用失败（网络、鉴权、响应解析不了） |
| `未配置模型密钥，已按子力价值兜底。` | 该棋手所属的连接没配 api-key |
| `棋手所属的模型连接不可用，已按子力价值兜底。` | 棋手的 `provider` 引用了不存在的连接名 |

兜底的启发式打分（`chess.FallbackPicker`），优先级从高到低：

1. 将杀（SAN 带 `#`）
2. 升变，升成价值高的子优先
3. 吃子：先吃价值高的，吃同样的子时用价值低的子去吃
4. 将军（SAN 带 `+`）
5. 易位
6. 往中心走

另外，不吃子、不易位的王步会被扣分，避免无故走王；同分时随机打散。
它不算「吃完会不会被吃回」——那要算攻击关系，等于在后端再写一份规则。
兜底只求不卡住对局，不求下得好。

**模型只问一次，不重试。** 重试就是再等一整轮推理，答案多半还是同样的，不如直接兜底。

### 完整示例

请求：

```json
{
  "playerId": "xuanji",
  "side": "b",
  "fen": "rnbqkbnr/pppp1ppp/8/4p3/4P3/5N2/PPPP1PPP/RNBQKB1R b KQkq - 1 2",
  "history": ["e4", "e5", "Nf3"],
  "legalMoves": [
    { "i": 0, "uci": "b8c6", "san": "Nc6" },
    { "i": 1, "uci": "d7d6", "san": "d6" },
    { "i": 2, "uci": "g8f6", "san": "Nf6" }
  ]
}
```

（示例为了简短只列了三条，实际要把全部合法着法都列上。）

响应：

```json
{ "index": 0, "reason": "出马保护 e5 兵。", "fallback": false }
```

## 错误响应

非 2xx 一律是这个结构（`ApiError`）：

```json
{ "code": "INVALID_REQUEST", "message": "side 必须匹配\"[wb]\"" }
```

| HTTP | `code` | 触发条件 |
|---|---|---|
| 400 | `INVALID_REQUEST` | 字段校验没过。`message` 是第一条错误，形如 `side 必须匹配"[wb]"`、`fen 不能为空`、`legalMoves 不能为空`、`legalMoves[0].san 不能为空` |
| 400 | `MALFORMED_BODY` | 请求体不是合法 JSON |
| 404 | `UNKNOWN_PLAYER` | `playerId` 在配置里找不到，`message` 形如 `未知的棋手：wukong` |
| 404 | `NOT_FOUND` | 路径不存在 |
| 405 | `METHOD_NOT_ALLOWED` | 方法不对，比如对 `/api/chess/ai/move` 发 GET |
| 4xx | HTTP 状态名 | 其余由 Spring MVC 判定的请求错误，`code` 取状态名，如 `UNSUPPORTED_MEDIA_TYPE` |
| 500 | `INTERNAL_ERROR` | 没预料到的服务端故障。`message` 固定是 `服务内部错误`，细节只进日志 |

再强调一次：**模型侧的任何问题都不会走到这里**，它们表现为 200 + `fallback: true`。

## 排查

服务端把发给模型的**完整请求体**和模型的**原始响应体**全量打进日志，没有开关，
前缀是连接名（`LlmPayloadLogger`），另有每次调用的耗时与 token 用量。
某一手拿到了 `fallback: true`，去日志里按棋手 id 和连接名找这一轮的报文，能直接看出是哪一环断的。
日志格式见 [`api-jungle.md` 的「排查」一节](api-jungle.md#排查)。
